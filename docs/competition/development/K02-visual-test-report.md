## 1. 实现范围

| 故事 | 实现与边界 |
| --- | --- |
| 布局与裁图 | `OcrLayoutParser` 严格 JSON 解析 grounding 区域，校验 0..999 范围和几何顺序；`VisualCropper` 解码前检查尺寸，按真实原图裁剪。无可靠框/裁剪失败显式整页兜底，未伪造局部坐标 |
| 私有保存 | V004 增加私有 PNG BLOB 和页状态表，绑定文档版本、解析修订、页号。图像和页检查点在同一租约事务保存；源指纹变更时替换本修订的派生图；删除文档级联清理 |
| 图文/分题 | 原文图注、邻近文字、公式及可靠行首题号保留；分题为启发式、需核验。可靠题号关联整段题干范围，避免长题后续片段丢图；无可靠锚点按页关联 |
| 检索展示 | `RagSearchHit.visuals` 携带真实来源元数据，当前 active chunk 决定版本；教师原页核验、含图检索和出处抽屉通过鉴权取图，不公开URL或密钥 |
| 回答读取 | 默认 DeepSeek-OCR 读取实际命中图片，再把标明来源的观察交给文字模型。显式开启 `RAG_CHAT_ATTACH_IMAGES` 才向支持视觉的非 GPT 回答模型直接附PNG；同步/流式共享图像引用与失败提示 |

上限：每页最多 6 图，单图 1 MiB，单文档版本/解析修订 32 MiB；回答最多 2 张去重图片、总计 2 MiB、每图默认 15 秒。提取 worker 与图像读取器各自最多 2 个 OCR 调用槽，不能合称所有 OCR 全局仅 2 并发。旧资料不自动付费升级，需要重新解析。

## 3. 真实样本与质量边界

真实测试从原课件裁出单页 PDF，保留原件名、原页号、原件 SHA-256，副本页号为 1。生产提取、OCR、私有保存、实际 chunk 关联和图像读取使用 Java 实现；隔离 H2，Embedding 禁用。原件散列未变，不修改业务资料。

- 第4章第10页：真实检测到 1 张激活函数局部图，裁图保留坐标轴和图例，约25 KiB。`Parse the figure.` 虽正常返回，却生成明显错误的曲线数值表，不能算语义正确。
- 第5章第14页：未返回可靠局部图框，实际保存整页兜底，约868 KiB。图像读取返回单核/多核、灰度/RGB等可见文字，不能据此声称所有箭头和空间关系均正确。
- 第3章第23页：保存整页参考图，约198 KiB，图像读取返回公式与文字；公式正确性仍沿公式专项的教师核验边界。

针对曲线错误的双提示真实诊断中，详细描述提示又虚构了多面板与论文出处，因此未采用。识别返回 HTTP200、非空或可排版均不代表数学或图意正确。直接 VLM 入口目前是受控协议验证，未擅自更换用户的文字回答模型，也未称已完成真实视觉回答模型验收。

最终真实复验中，第4章第10页的生成数值表被拦截，传给文字回答模型的内容只有 `ReLU / Leaky ReLU / ELU / Softplus` 可见标签，明确“未读取曲线数值”。第5章第14页也触发了保守回退；第3章第23页保留非数表观察。数表检查不能判断某个数值是否真的印在原图上，因此可能同时限制真实表格的数值型解读；原始OCR、公式、原页图仍保留，没有据此删掉入库的原文。此流程不是通用图形理解或定量图表识别验收。

本轮未重跑全部334页和原先20页扫描集；未宣称完成K03召回质量、图搜图、自动正确解题或教师审校发布。基础题号分组不等于复杂试卷语义分题。手写、跨页续题和重复题号仍需核验。

## 4. 真实失败及修正链

1. 先写布局、裁图、保存、看图及页面用例，缺类/方法或缺UI产生真实红灯。子Agent记录各自独立导出，未把fork父记录重复算为子执行。
2. 标题被题号过滤掉，先加断言失败再保留邻近原始标题；后续长题多chunk又复现“所有图锚到公共标题”，改为可靠题号的连续范围。
3. 纯图片OCR无正文原先标FAILED并丢出检索；加入显式“图像来源信息，非OCR正文”，且只有实际图像保存成功才能作为来源。容量耗尽时只剩占位说明的错误也有单独红灯，再修为失败/不入索引。
4. 同一修订的FAILED页恢复时可能沿用旧派生图，真实回归失败后增加源指纹检查和事务替换；相同内容再次检查保持幂等。
5. 读图前后必须核对实际 active chunk 与图像关联；换版、撤权和取消有失败测试后修正。一个重新stub触发的Mockito空值错误按fixture问题记录，不冒称功能红灯。
6. 引用抽屉新响应缺少图片字段时会残留旧图，前端失败用例后修复；分题展示还通过截图发现编号被重排/选项挤行，按实际红绿记录修正。
7. 真实曲线内容错误以及详细描述提示虚构内容，保留诊断统计和私有原文，按可核验文字回退处理，不靠非空输出通过质量验收。
