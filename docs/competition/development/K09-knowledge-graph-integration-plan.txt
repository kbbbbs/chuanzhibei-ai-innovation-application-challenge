课程知识图谱接入方案：单章节试点
版本：建议方案 v1.0｜2026-11-15
适用项目：D:\ai-learning-collaboration-verified
状态：方案交付，尚未实施本方案中的 Neo4j、图查询接口或自动抽取。

一、目标与范围

建设以课程知识实体及其语义关系为核心的知识图谱：知识点有统一身份、类型、解释和来源；关系有明确方向、含义和依据；数据持续保存在图数据库中，支持邻居查询、路径查询和更新；前端提供可以拖动、缩放、筛选和展开的关系网络。

首期沿用《第2章-机器学习概述-okk.pdf》作为试点章节。正式导入时必须先将资料纳入现有课程资料管理，取得真实 documentId、documentVersion、parseRevision、indexVersion 和 chunkId，再绑定图谱证据。现有前端文件中的页码可作为整理线索，不能代替后台资料身份或访问授权。

用户故事：
1. 学生进入某课程章节，看见已发布的知识网络，能找到一个知识点以及它与其他知识点的关系。
2. 学生点击节点或关系，看到解释、来源页码，并能在授权范围内查看原文。
3. 教师核对本章实体、关系及学习先后关系后发布；修改资料后能看见图谱需要更新的状态。

范围：本章知识整理、图数据库存储、真实查询接口、交互展示、审核发布与来源追溯。跨课程实体融合、自动个性化学习推荐、复杂本体推理和图增强问答安排在后续阶段。

与原实施方案关系：原确认版明确把“自动图谱”排除在当时版本之外。本方案是根据本轮新需求提出的增量，归入 K09 课程知识展示，涉及 K03 资料处理与 K05 课程权限；不把新增范围表述为已经完成的原定能力。

二、两篇参考文章如何落到本项目

参考一《如何在Java中实现高效的知识图谱：从构建到推理》提供构建、存储、查询及推理的整体思路。本项目采用属性图描述实体、关系和属性；首期不同时引入 RDF/OWL/Jena 技术链。学习路径查询与严格逻辑推理分别设计，不能把“存在一条路径”称为“证明了一个知识事实”。
https://blog.csdn.net/weixin_44409190/article/details/141873409

参考二《Spring Boot2 集成 Neo4j 实现知识图谱》展示 Spring Boot 接 Neo4j、节点/关系查询及圆形节点网络界面；文章列出 Cytoscape.js、D3.js、vis.js 等前端选项。本项目采用其中的后端图查询和网络探索思路，并增加课程权限、证据、审核和版本控制。
https://blog.csdn.net/lovelichao12/article/details/116425151

文章示例年代较早，出现 Spring Boot 2、旧 Driver 包和旧服务端配置。本项目当前为 Java 21、Spring Boot 3.5.16，应使用项目依赖管理与对应文档，不照搬旧版本、原始 Cypher 输入接口、字符串拼接查询或数据库内部节点 ID。

三、推荐技术组合与整体架构

推荐：Vue 3 + Cytoscape.js → 现有 Spring Boot 后端 → Neo4j。
保留 MySQL 及现有 RAG 文档、OCR、切片和检索体系。

课程资料
  → 现有解析/OCR、切片、索引发布
  → 章节范围选择
  → 人工整理或模型抽取候选实体与关系
  → 校验、实体归一、教师审核
  → MySQL 保存已确认快照和待同步事件
  → 后台任务写入 Neo4j 的独立图谱版本
  → 检查完整性后发布
  → 图查询 API
  → Vue 中的关系网络、详情和来源面板

职责明确为：
1. MySQL：用户/课程/资料权限、原文与切片引用、候选结果、审核记录、已确认图谱快照、任务及发布版本。已确认快照是图谱事实的恢复依据。
2. Neo4j：已确认图谱的持久化查询副本，保存节点、类型化关系与版本/证据标识，执行邻居与路径查询。禁止绕过审核流程把 Neo4j 改成另一套独立编辑来源。
3. 后端：统一认证授权、建图任务、图谱版本控制、固定查询模板与结果转换。
4. 前端：展示后端返回的 nodes/edges，不直连数据库；画布位置与知识事实分开。

选择 Neo4j 是本项目对持久化关系查询的实现选择。知识图谱的关键在于语义、身份和依据，不由节点外形或是否采用某个数据库单独决定。

后端首期使用官方 neo4j-java-driver 和明确的 Cypher 查询模板，便于控制关系类型、查询深度和权限范围。由 Spring Boot 管理兼容依赖，使用 spring.neo4j.* 配置。暂不额外引入 Spring Data Neo4j 的对象映射层，避免两套访问方式重复。
https://docs.spring.io/spring-boot/3.5/reference/data/nosql.html#data.nosql.neo4j

前端新增 Cytoscape.js。它提供图布局、节点交互和网络分析接口，适合本次探索式界面；首期可用内置 CoSE 布局，验证需要后再引入布局扩展。现有 Vue Flow 示例保留为历史演示，正式章节入口改读图谱 API。
https://js.cytoscape.org/#layouts

四、实体、关系与证据模型

4.1 实体

统一使用 KnowledgeEntity 标签，以 entityType 区分知识概念、方法/算法、学习任务、模型、评价指标等；Course、Chapter 用于组织范围。DocumentVersion、Chunk 可以在图中保留轻量引用，完整原文仍由现有资料服务管理。

首期建议实体例子：机器学习、监督学习、无监督学习、分类、回归、模型、损失函数、优化算法、梯度下降。是否细分更多实体取决于本章原文，不规定人为凑齐的节点数量。

关键字段：
- entityId：应用生成的稳定 ID，不使用 Neo4j 内部 id。
- graphId、graphVersion：查询与发布隔离范围。
- entityType、name、normalizedName、aliases：身份、类型及同义词。
- description：有依据的简要解释；跨来源合并时保留解释与来源的绑定。
- reviewStatus、origin：审核状态及人工整理/模型候选等来源。

同一概念在同一课程范围内优先复用 entityId。同名不同义的实体不强行合并；首期不做全平台同名实体融合。别名字符串归一只能生成合并候选，最终结合类型、上下文和教师审核确定。

4.2 类型化关系

关系代码 | 中文含义与方向 | 建模约束
HAS_CHAPTER | 课程 → 章节 | 结构关系
COVERS | 章节 → 知识实体 | 章节覆盖，不代表学习依赖
IS_A | 子类/具体类型 → 上位类型 | 需明确分类依据
HAS_TASK | 学习方式 → 任务类型 | 如监督学习 → 分类、回归
HAS_EXAMPLE | 一类方法 → 具体方法 | 如优化算法 → 梯度下降
USED_FOR | 方法/模型 → 任务 | 保存适用条件，不能把常见用途写成唯一用途
MEASURED_BY | 被评价对象 → 评价方式 | 由原文或教师核对确定
PREREQUISITE_FOR | 先学知识 → 后学知识 | 教师确认的教学依赖，不从页码先后自动推断
RELATED_TO | 实体 ↔ 实体 | 仅在有明确解释时使用，不作为无法分类关系的默认兜底

实际首期只启用本章确有依据的关系类型。关系白名单同时规定允许的起终点类型、方向和必要属性。一般语义图允许多对多和环；教学先修子图在发布前检查循环，避免生成互相依赖的学习顺序。

关系关键字段：relationId、sourceId、targetId、relationType、explanation、qualifier、origin、reviewStatus、graphId、graphVersion。不同语义可并行连接同一对实体；相同事实不因重复导入生成重复边。

说明性三元组：
  监督学习 —任务类型→ 分类
  监督学习 —任务类型→ 回归
  优化算法 —算法示例→ 梯度下降
  损失函数 —建议先学→ 梯度下降〔待教师确认〕
前三项可从现有章节整理结果复核；最后一项是教学建议，不能作为已审核先修事实直接发布。跨分支连接应来自原文或有署名的教师判断，不为使画面像网状而添加事实。

4.3 证据

每条发布的知识事实关联一个或多个 evidenceId。文献证据保存 documentId、documentVersion、parseRevision、indexVersion、chunkId、pageNo 或其他定位符、charStart/charEnd、短证据片段和摘要指纹。教师新增教学关系保存教师身份、确认时间、理由及参考内容，界面标明“教师建议”。

同一关系可以有多条证据；不同证据不一致时进入待复核状态。模型自报 confidence 只能用于审核排序，不能作为正确率或自动发布门槛。节点解释也必须能追溯，不能只给关系留来源。

五、构建、更新与发布流程

第一步：资料准备。复用 RagIngestionService 的现有解析、OCR 和切片结果，从已授权且稳定的文档版本选择本章。首次试点允许教师确认页码范围，无须先实现全书章节识别。章节和现有课时的映射需要显式保存，不能默认二者相同。

第二步：生成候选。第一阶段使用人工核对的 JSON/CSV 导入，将知识实体和语义关系真实写入数据库；第二阶段再接现有非 GPT 产品模型做受约束的结构化抽取。复用现有 ChatModelClient 抽象需先验证超时、返回格式和模型配置，不能因使用兼容 SDK 而更换已确认模型策略。Embedding 继续 Qwen/Qwen3-VL-Embedding-8B，OCR 继续 DeepSeek-OCR；二者不等同于关系抽取模型。

抽取输入包含选定切片及其真实 ID。输出限定实体类型、关系枚举、端点、原文证据及位置；先验证 JSON 结构、端点存在、证据匹配与范围，再做别名归一和去重。无证据、超出章节范围、内容冲突或格式异常进入待处理列表。首期人工审核所有拟发布事实，保留修正前后及实际模型版本、提示版本。

第三步：审核。教师可修改名称、类型、别名和关系，合并/拆分实体，驳回候选，确认教学依赖。候选、教师确认和资料明确陈述在界面区分。保存草稿不改变学生端已发布版本。

第四步：持久化和发布。MySQL 事务一次提交已确认快照及待同步事件；后台按 graphId + graphVersion 投影到 Neo4j，使用稳定应用 ID 与幂等写入。完成端点、证据、数量和范围检查后，在 MySQL 切换发布指针。写图失败可重试，旧版在仍有权限且来源有效时继续使用。不要假设一个普通 @Transactional 就能同时原子提交 MySQL 与 Neo4j。

建议状态：QUEUED → BUILDING → REVIEW_REQUIRED → PROJECTING → READY → PUBLISHED；另设 FAILED、STALE、RETIRED。任务进度可查，失败原因能说明，重试不重复创建实体。

第五步：资料变化。保存输入文档/解析/切片版本指纹；重解析或重建索引后，旧 chunkId 不一定继续有效。先标记受影响图谱过期，按证据重新映射/抽取与复核，再发布新版本。权限撤销和资料删除必须立即阻断相关展示，不能等异步清理完成才拒绝访问。历史版本只在原文快照仍存在、授权仍有效且用户主动查看历史时呈现，不混入当前版本。

六、后端接口建议

统一前缀 /api/rag/graphs，沿用项目身份和响应约定；以下为拟新增契约，并非已存在接口。

方法与路径 | 作用
POST /api/rag/graphs | 以 courseId、chapterId、明确资料版本/页码范围创建建图任务；返回 graphId/jobId，异步接受
GET /api/rag/graphs/{graphId}/jobs/{jobId} | 查询构建、审核或同步状态
GET /api/rag/graphs/{graphId} | 获取指定可见版本的章节子图、类型统计与版本信息
GET /api/rag/graphs/{graphId}/entities?keyword=... | 查名称和别名，分页返回
GET /api/rag/graphs/{graphId}/entities/{entityId}/neighbors | 按关系类型、方向、深度展开相邻知识
GET /api/rag/graphs/{graphId}/paths?from=...&to=... | 查询受限长度的关系路径或已审核先修路径
GET /api/rag/graphs/{graphId}/evidence/{evidenceId} | 验权后获取依据及原文定位
PATCH /api/rag/graphs/{graphId}/draft | 教师修改待审核实体/关系，携带版本号避免覆盖并发修改
POST /api/rag/graphs/{graphId}/publish | 教师发起发布，校验权限、来源和草稿版本

图数据契约至少包含 graphId、graphVersion、status、nodes、edges、truncated、warnings。节点包含 id、name、type、evidenceCount；边包含 id、source、target、type、label、reviewStatus。详情与大段原文按需加载；统计只基于调用者可见数据。

初始查询建议限制为最多 100 个节点、200 条边，邻域深度 1–2；路径深度与结果条数另设硬上限并提供超时。以上为待压测的工程初值，不是已测性能。截断时明确提示并允许继续展开，不能让用户误以为结果已完整。

前端不提交任意 Cypher，不提供教程式 getCypherResult(cypher) 公共入口。参数采用绑定；标签、关系类型和排序方式采用服务端白名单或固定模板。Session 按请求/任务使用并关闭，在事务内完成结果读取和 DTO 转换；不要把惰性 Result 带出会话。
https://neo4j.com/docs/java-manual/current/transactions/

七、前端体验与原有页面调整

页面结构：顶部课程/章节、搜索框和关系筛选；中央圆形节点知识网络；右侧节点/关系详情及来源；底部图例和当前图谱版本状态。使用现有产品配色，可采用参考界面的网络布局，不照搬广告或数据库管理界面。

首期交互：
- 圆形节点按实体类型区分颜色，文字可读；语义关系展示箭头和中文名称，多条关系用不同曲线区分。
- 拖动节点时连线跟随；拖动画布、缩放、适应全图、重新布局。
- 点击节点高亮一阶关系；双击或“展开”按钮请求后端邻居，保留已移动位置。
- 搜索名称和别名，定位节点；筛选关系后保持布局稳定。
- 点击关系显示起点、终点、含义、审核标记和证据；点击证据回到授权原文。
- 选择两个知识点查看关系路径；“学习顺序”只沿审核后的先修关系计算，明确它不等同于任意最短路径。
- 加载、空图、无权限、过期和后端故障分别展示；没有真实图谱时显示状态，不自动填入示例冒充结果。
- 提供关系列表和键盘可用的详情入口，兼顾窄屏；拖动只改变视图位置，不新增或修改知识关系。

默认图谱可隐藏课程/章节组织节点，优先显示知识实体之间的语义关系；用户可切换组织层级。节点可多向关联，不能强制每个节点仅有一个父节点。实际资料只有树状关系时忠实展示，不人为扩展。

九、权限、版本和部署要求

权限以 MySQL 的实际课程资料授权和有效版本为准。教师建图前验证资料使用权；学生查询前验证课程访问权、章节范围、可用资料版本。图中每个节点解释、关系证据及路径中间节点都要可见；不得只检查起点、终点。搜索联想、数量统计、缓存和合并后的描述同样受限。

实施时优先按统一有效授权范围构建/发布图谱；若一个图包含不同可见性的来源，查询前限定合法事实集合，依据可见证据重新生成详情/计数，不能返回融合了隐藏来源的描述。读取完成、返回响应前再次校验授权/版本；缓存键必须包含授权范围和图谱版本，撤权立即失效。

部署增加一个独立 Neo4j 服务及持久化数据卷。固定与当前驱动验证兼容的受支持版本，在实施日核对版本矩阵并锁定镜像；本方案不指定未经当前环境验证的镜像标签。数据库端口只向后端/本机管理开放，账号配置置于私有环境变量，不进入源码、浏览器或开发记录。配置连接超时、查询超时、健康检查及备份恢复。首期不依赖 APOC、企业专属算法或额外图计算集群。

图谱开关可单独关闭。图服务故障时返回真实不可用状态，现有 RAG 检索按原路径工作；已确认快照可用于重建 Neo4j，但仍必须经过来源和权限校验。

十、与 RAG 的分期关系

第一阶段共享资料、切片和证据体系，只完成图谱构建、查询与展示，不改变现有问答召回。

后续可增加图增强检索：问题识别实体 → 有权访问的图邻域/先修关系 → 对应原文切片 → 与现有关键词/向量结果合并去重 → 重排 → 带原文引用回答。图的边与路径用来定位资料，不能自动代替原文证据。不得让大模型生成任意 Cypher 直接执行。

这一步必须先补齐课程/课时有效资料范围，单独冻结评测问题集，对比原 RAG 和图增强 RAG 的引用正确性、答案质量、延迟与失败情况。现有检索曾有未达到目标的评测记录，不能预先宣称引入图谱一定提升效果。若增益不足或图服务失效，保留原检索作为回退。

知识推理也单列后续目标：先提供明确规则下的先修链查询，并标注推导路径和依据；复杂 OWL 推理、关系预测和个性化推荐需要独立需求、质量评估及数据支持。

十一、实施阶段、验收与工作量

阶段 A｜打通一个真实章节｜预计 2–3 人日
建立 Neo4j、图谱版本和基本授权；将已核对实体/关系作为人工整理候选导入并确认；完成后端章节子图/详情/邻居接口。启动后能从数据库读出该章图谱，重启后数据仍存在，重复导入不重复造点造边。章节大小和覆盖范围据原文确定。

阶段 B｜网络可视化｜预计 2–3 人日
完成 Cytoscape 圆形网络、关系标签、拖动缩放、搜索筛选、展开和证据面板。页面实际请求图 API；后台新增并发布一个经确认的关系后，刷新能看到，前端无需修改静态数组。

阶段 C｜可发布的课程试点｜预计 2–3 人日
完成教师审核/发布、学生授权展示、资料更新失效、任务重试、路径限制与必要回归。学生端只显示审核后的有效版本。A–C 合计粗估 6–9 人日，前提是当前课程授权链可复用；若需补齐 K05 的课时范围则另行计入，不能当作现成能力。

阶段 D｜自动抽取｜另预计 3–5 人日
增加模型候选抽取、别名合并候选、证据匹配和修正复核。单章节全量人工核对；记录遗漏、错误实体、错误关系及人工修正比例，不能用模型 confidence 代替准确率。模型接入限制和课件复杂度可能增加工作量。

以上是规划估算，不是已完成工时或交付承诺。人日不因任务拆分自动等于可并行的日历天数。图增强 RAG 和复杂推理不包含在估算中。

按 Scrum + XP 实施：每个故事先编写有意义的验收/集成测试并观察真实缺失行为，再小步实现和回归；测试环境的异常不能冒充产品功能的失败证据。建议至少验证：
1. 真实 Neo4j 的导入、重启读取、重复任务、事务失败和版本切换；数据库行为不只依赖模拟对象。
2. 所有返回边的端点存在，关系类型/方向合法；所有发布事实有可解析的资料证据或明确署名的教师依据。
3. 非成员、另一课程教师、未发布版本、撤权和已删除资料不能通过图、搜索、路径、统计或证据接口泄露信息。
4. OCR 重跑、文档更新、重建切片后，旧证据不会被当成当前来源；重试不污染已发布版本。
5. 模型返回无效 JSON、虚构切片、缺失端点或章节外关系时不能直接发布。
6. 实际浏览器中拖动/缩放/搜索/展开/关系详情、窄屏和加载失败均可操作；高亮或筛选不重置拖动位置。
7. 教师逐项核对试点章节的实体、语义关系、学习建议与证据，确认所选范围的覆盖情况。
8. 运行相关后端测试、现有 RAG 页面回归及前端构建；记录真实环境、耗时、失败与跳过原因。查询速度设为待测指标，先记录单章基线，不宣称未测的吞吐量。

人工演示脚本：选择第2章 → 查看知识网络 → 搜索“监督学习” → 展开“分类/回归” → 拖动节点并检查关系标签 → 查看一条边的来源 → 查看一条教师确认的学习路径 → 教师修改草稿并发布 → 学生刷新查看新版本。

十二、本轮结论与交付边界

建议先实施阶段 A–C，得到一个真实持久化、可查询、可追溯的单章节知识图谱，再接自动抽取与图增强问答。
