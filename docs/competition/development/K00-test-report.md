# K00 实施与验证结果

日期：2026-10-20。范围：后端 K00“固化工作区和模型契约”。需求依据为已确认的代码实施方案及 D01–D10。人工操作见 [K00 人工验证方法](K00-manual-verification.md)，入口盘点和用户故事见 [K00 模型入口审计](K00-model-entrypoints.md)。

## 1. 本轮结果

K00 代码、配置、自动测试及人工验证说明已完成。生成、规划、Embedding、OCR 分为四种配置；生成和规划可独立设端点、密钥与模型，规划未设置字段时明确继承生成设置。支持 `BASE_URL` / `API_KEY`，同时保留现有 `AI_OPENAI_*` 变量。

当前进程未提供 `BASE_URL`，但已有旧命名的模型地址、密钥和模型名。真实探测使用这些现有设置，未输出或写入真实密钥，未自行选择其他供应商。

生成模型同时覆盖 Agent、备课、资料出题和原生 RAG 问答。规划器、参数提取/修复及兼容动作选择走规划模型。移除了清空不兼容 Agent 模型名的静默替换；默认模型及请求级 model 覆盖均在同步、流式和框架公开内部方法中检查。关闭 SDK 隐式模型自动配置，缺配置仍能启动，但模型调用明确失败。

新增仅管理员可用的只读 `GET /api/admin/models/status` 和显式 `POST /api/admin/models/{role}/probe`。状态查询不访问模型；主动探测分项显示结果，不把“配置存在”标为通过。旧模型健康检查保留，但限制管理员。HTTP、流式截止及向量超时已验证；上游模型异常转换为安全错误，不向业务调用方传递原始响应正文和可遍历的供应商异常链。

OCR 模型保持空值，本轮没有实现或冒称完成 OCR 识别。K01 数据和权限、K02 解析/OCR、K03 语义索引、K04 课程问答仍按实施方案后续推进；K00 的基本 Embedding 探测不代表语义质量验收。

## 4. 真实接口观察

两轮均使用环境中已有的生成配置，规划按既定规则继承；没有换模型、改提示或放宽断言。探测仅发送合成测试文字，各分项最多输出100 tokens，真实测试每次调用时限8秒。

| 能力 | 首轮生成 | 最终生成 | 首轮规划 | 最终规划 |
| --- | --- | --- | --- | --- |
| 普通响应 `TEXT` | PASS | PASS | PASS | PASS |
| JSON 对象 `JSON_OBJECT` | PASS | PASS | PASS | PASS |
| 流式 `STREAM` | PASS | PASS | PASS | PASS |
| 2432字符样本 `CONTEXT_SAMPLE` | FAIL | PASS | PASS | PASS |

首轮生成的上下文样本返回不满足严格标识匹配，按用户约定将该真实测试标记待复验的跳过，并保留失败结果。传输和诊断修复后对最终版本复验，两个角色各4项通过。这个波动说明不能凭一次通过承诺稳定质量；尚未验证最大上下文、长期稳定性或课程内容正确率。

最终生成分项耗时约0.83、1.43、1.20、2.11秒；规划约1.65、1.26、1.22、1.60秒。这些是单次观测，不是性能门槛或统计结果。首轮及最终安全 JSON 已收入 [K00 验证快照](K00-verification-snapshot.json)。Embedding 和 OCR 未做真实外部接入验证；各自需要后续模型配置与相应任务验收。

构建命令 `mvn -DskipTests package` 成功，产物为后端 `target/Final_exam_question_bank-0.0.1-SNAPSHOT.jar`。打包跳过重复测试，依据是同版源码此前的全量回归；打包成功未替代功能测试。

## 5. 人工复验顺序

1. 按 [人工验证方法](K00-manual-verification.md) 的第1–2节确认变量并启动演示环境，以管理员登录。
2. 先查看四类模型状态；用学生/教师账号确认权限拒绝。
3. 主动 POST 生成和规划探测，逐项查看 `checks`，特别保留上下文样本的成功和失败记录。
4. 如接口引用失败，补充本机 `.env.local` 中的非 GPT 模型配置并重启，再重复第3步。OCR模型继续留空。
5. 在进入 K01 前，以本轮快照为起点记录新增需求或配置变动；无需重新改写已确认的 D01–D10。
