## 2. 开发前入口审计

以下路径均相对于 `ai-learning-backend/src/main`，描述开发前观察到的调用结构。

| 能力或业务 | 文件 | 观察与 K00 处理目标 |
| --- | --- | --- |
| 生成配置 | `resources/application.yml` | 现有生成服务使用兼容协议配置；需统一解析配置来源、缺配置状态和有效模型约束。 |
| Agent 生成 | `java/com/cupk/aiacademy/agent/core/llm/SpringAiChatModelClient.java` | 实现 `ChatModelClient`，调用 `OpenAiChatModel` 的同步与流式接口。两种路径均需使用受检查的生成模型。 |
| 生成抽象 | `java/com/cupk/aiacademy/agent/core/llm/ChatModelClient.java` | 已有生成抽象。可扩展规划调用契约，复用现有调用边界，避免另建一套业务模型框架。 |
| 规划 | `java/com/cupk/aiacademy/agent/planner/PlannerModelClient.java` | 通过 `ChatModelClient` 调用，且可用 Prompt options 覆盖模型。需路由到独立规划配置，并检查实际生效模型。 |
| 规划属性 | `java/com/cupk/aiacademy/agent/planner/AgentPlannerProperties.java` | 已有规划超时、输出 token、温度等属性。保留业务参数，明确与统一规划模型配置的优先关系。 |
| 参数抽取与修复 | `java/com/cupk/aiacademy/agent/action/AgentParameterExtractor.java` | 抽取和修复各有一次模型调用。两处均应归入规划角色；本地参数推断需保留其可识别来源。 |
| 旧动作选择 | `java/com/cupk/aiacademy/agent/action/AgentActionSelectionService.java` | 已标记弃用的兼容实现仍有模型调用；保留代码时也需遵守规划路由和模型约束。 |
| Agent 模型覆盖 | `java/com/cupk/aiacademy/agent/core/prompt/AgentPromptAssembler.java` | Agent 定义中的 model 可写入 Prompt options，不能只验证默认模型配置。 |
| Agent 模型回退 | `java/com/cupk/aiacademy/agent/core/service/AgentChatService.java` | 存在 DeepSeek 供应商下清空不兼容 Agent model 的静默替换逻辑。需避免违规模型在检查前被替换，从而掩盖实际配置问题。 |
| 智能备课 | `java/com/cupk/aiacademy/preparation/PreparationModelGateway.java` | 直接注入 `OpenAiChatModel`，并有重试与 JSON 修复。应由受检查的生成模型覆盖，不要求本轮重写备课流程。 |
| 原生 RAG 问答 | `java/com/cupk/aiacademy/rag/chat/NativeRagChatService.java` | 直接注入 `OpenAiChatModel`，包含同步和流式调用；两条路径均需遵守生成配置与禁止隐式回退的约束。 |
| 教师出题 | `java/com/cupk/aiacademy/service/QuestionService.java` | 直接模型调用支持模型覆盖；另外部分路径复用备课生成逻辑。需同时检查默认与覆盖模型。 |
| Embedding | `java/com/cupk/aiacademy/rag/RagEmbeddingClient.java` | 通过独立 HTTP 客户端调用向量服务，已有独立配置。K00 统一其配置契约与缺配置状态，不实现索引版本重建。 |
| 旧 OCR | `java/com/cupk/aiacademy/weknora/service/OcrService.java` | 现有实现属于旧 WeKnora 集成，使用 Tess4J。不能把它视为新 OCR 模型已接入。 |
| 旧 OCR 配置 | `java/com/cupk/aiacademy/weknora/config/OcrConfig.java` | 属于旧服务配置。新 OCR 角色的模型字段保持为空，不自动沿用 Tesseract 或生成模型。 |
| 现有模型健康检查 | `java/com/cupk/aiacademy/agent/core/controller/AgentModelController.java` 与 `agent/core/llm/AgentModelHealthService.java` | 旧 GET 健康检查会实际调用生成服务。新增只读状态必须与主动探测区分；保留兼容入口时需检查访问权限及调用行为。 |

`OpenAiChatModel` 是协议适配类名，不能据此判断运行时使用 GPT。验收应检查有效服务配置、请求中的实际 model 以及真实调用证据。禁止把兼容协议本身认定为违规，也不能因为使用兼容协议就默认允许任何模型。

## 3. K00 目标配置与接口

计划建立 `runtime.models` 下四个角色的配置契约：

| 角色 | 目标行为 |
| --- | --- |
| `generation` | 为 Agent 问答、备课、出题及原生 RAG 生成提供统一且受检查的服务。支持现有配置与用户指定环境配置的兼容解析；优先级应在测试和说明中一致。 |
| `planning` | 与生成角色独立，可明确继承生成配置，也可单独覆写；规划、参数抽取及修复使用本角色。继承是明确规则，不能在调用失败后切换服务。 |
| `embedding` | 独立配置，不因生成服务可用就宣称向量服务可用；缺配置应有明确状态。 |
| `ocr` | 独立配置，具体模型留空。K00 只提供配置和状态契约，真实模型接入与逐页管线属于 K02。 |

生成与规划的配置缺失应允许应用启动，调用时返回明确的未配置状态。配置与调用检查必须覆盖请求级模型覆盖、同步调用和流式调用；不得静默选择 GPT、隐式默认模型或其他供应商。

计划提供下列管理员接口，具体请求及响应结构以实现后的接口说明为准：

| 接口 | 草案用途 | 验收重点 |
| --- | --- | --- |
| `GET /api/admin/models/status` | 获取四个角色的配置状态及能力检查状态。 | 必须只读且不发起外部模型调用；只返回适合展示的状态，不返回原始配置对象。 |
| `POST /api/admin/models/{role}/probe` | 管理员明确触发指定角色的能力探测。 | 校验角色、限制访问、区分缺配置与调用失败，分项记录实测结果。 |

生成与规划可按适用性探测普通输出、结构化输出、流式输出和指定长度上下文样本。探测只证明该次样本与当前配置下的表现，不能由短样本推断模型最大上下文窗口。Embedding 与 OCR 应按各自协议报告适用或暂不可探测状态，不能借用生成结果充当通过证据。

## 6. XP 开发与验收清单

### 测试先行

- [ ] 在对应实现前编写配置、模型守卫、角色路由、状态及探测接口的测试。
- [ ] 执行新增测试并保留预期失败的简要证据；区分测试确实未通过与测试环境未能执行。
- [ ] 以满足测试的最小实现推进；实现通过后再重构重复配置或调用逻辑。
- [ ] 重构后重跑受影响测试与必要业务回归，记录最终结果和限制。

### 配置与边界

- [ ] 四角色配置隔离；规划明确继承或独立覆写时解析正确。
- [ ] 无模型配置时应用可启动，调用返回稳定、可理解的未配置状态。
- [ ] 请求级 model 覆盖和默认 model 均检查，大小写及首尾空白不形成绕过。
- [ ] 对明确的 GPT/OpenAI 运行模型及官方服务端点采用一致约束；兼容协议名称本身不触发误判。
- [ ] 受保护生成模型覆盖同步和流式调用，不发生静默模型替换或失败后供应商切换。
- [ ] Embedding 独立检查配置与实际响应，OCR 未选模型时维持未配置状态。

### 接口与探测

- [ ] 只读状态接口可重复查询且不会产生模型网络请求。
- [ ] 两个新接口均限制管理员访问；覆盖匿名、学生、教师和管理员场景。
- [ ] 探测拒绝未知角色，返回普通、结构化、流式及上下文样本的分项状态。
- [ ] 探测结果不把模型响应格式异常、超时或空结果当作通过。
- [ ] 探测结果不把模拟服务与真实服务混为一谈，不声称未经测量的最大上下文能力。

### 回归与交付

- [ ] Agent 生成、规划、参数抽取/修复、备课、出题、RAG 同步/stream 的入口得到覆盖或明确列出未覆盖项。
- [ ] 现有离线测试不因配置变化意外访问真实外部服务；完整上下文测试继续使用隔离数据库。
- [ ] 新增多个模型 bean 后注入关系明确，原业务的构造和测试不存在歧义。
- [ ] 保存本轮真实需求、测试失败、修正与最终执行记录，不补造开发对话、提交或测试历史。
- [ ] 输出实际测试结果、未验证项目及人工补配服务后的验证方法；未运行的项目保留“待验证”。

## 7. 完成定义草案

K00 完成应同时具备可审阅代码增量、测试执行证据、配置与接口说明、已知限制和人工验证步骤。真实模型探测能否完成取决于当前可引用配置与服务可用性；未完成的探测须说明原因和复验方法，不影响其余离线测试结果的独立报告。
