## 1. 使用本轮代码

关闭此前启动的后端，按 [K02 启动方法](K02-manual-verification.md)重新构建并启动。当前机器可先在 PowerShell 中设置：

```powershell
$env:JAVA_HOME = 'C:\Users\KBS-ROG\.jdks\openjdk-24'
$env:Path = 'D:\Workspace\apache-maven-3.9.16\bin;' + $env:Path
Set-Location D:\ai-learning
.\scripts\competition\start-local.ps1
```

另开终端，在 `D:\ai-learning\ai-learning-frontend` 执行 `npm run dev`，打开实际输出的地址。脚本默认隔离演示库。不要为了本次验收切换到业务库。OCR 继续读取已有独立配置；不需要重新提交密钥，也不需要 GPT 接口。界面公式库与字体随前端本地打包。

后端启动执行 V003 增量迁移，增加公式元数据列。**旧解析结果不会自动变成新公式结果**，也不会自动产生收费识别任务。

## 2. 旧资料重新解析

1. 以资料所有者教师身份进入知识库的“资料与出处”，找到课件，打开“逐页核验”。旧结果应显示“旧解析结果尚未检查公式”。
2. 可先对下表的少量代表页点击“强制识别本页”。核验整份资料时再点“重新解析全部”。“重建向量索引”不会重新进行 OCR，不能修复旧的扁平公式。
3. 等待处理结束，分别检查文档状态、失败页和需核验页。`COMPLETED` 仅表示任务结束；`PARTIAL` 表示仍有缺失页。
4. 重试会创建新的解析修订。未选中的页保留原检查点，因此逐页升级后仍可能同时存在新版公式页和待升级的旧页。

## 3. 逐项检查公式

| 原件位置 | 重点检查 |
| --- | --- |
| 第3章第14页 | 交叉熵的求和上下限、负号、类别下标及数值例子 |
| 第3章第23页 | 交叉熵、求和上下限、预测值帽号、矩阵/向量符号 |
| 第4章第10页 | 分段函数每个分支及条件；ELU 等价式是否遗漏；旁注是否混入等式 |
| 第4章第18页 | 复合式、上下标和导数 |
| 第4章第23页 | 梯度、偏导、行列向量排列；此前出现过输出截断 |
| 第5章第14页 | 普通图示文字和 `D=3` 等简单标记，避免为公式优化牺牲图示文字 |

“逐页核验”同时提供原页、公式排版、LaTeX 源码、文字层原文和模型原始结果。公式字符范围是识别文本的 UTF-16 偏移；不是图像坐标。来源应显示“图像识别”或“原始文本”，没有模型置信度时保持“服务未提供置信度”。

检查分母、正负号、上/下标、矩阵每行每列、分段条件、公式条数、变量定义与原页一致。**可排版、结构检查通过、处理就绪，都不等于内容审校通过。** 本版没有新增“人工修订公式并审批发布”的工作流；若仍有漏项，先保留问题记录，可上传核验后的 MD/TXT 作为单独的明确来源，不能把模型补写当作原文。

如果界面提示公式结构缺失/残缺或 OCR 截断，应有失败状态且该页没有本次可检索文本；其他成功页可以保持可用。可展开初次识别或调整图像尺寸前的原始结果。再次失败不会无限重试。重复调用产生的结果可能不同，不保证再识别一定修好内容错误。

## 4. 检索与回答

在同一知识库询问课件对应的定义，例如“请引用资料给出交叉熵公式，并解释其中的符号”。

- 有相关证据时，检查回答中的公式与引用片段、原页一致；参考资料抽屉应排版公式，并可展开“查看原文源码”。
- 矩阵中的 `[1]` 或 `[99]` 不应被误认作资料引用。真实引用编号仍应对应可打开的片段。
- 含公式的检索结果应保留核验提示。LLM 新推导必须与原文区分，不应擅自补全无法识别的公式。
- 缺少相关证据时，应提示证据不足；不能为了展示公式而编造教材内容。K03 召回质量仍另行验收。

可另建测试库，上传 UTF-8 Markdown 测试资料，验证纯文本公式不依赖 OCR：

```markdown
样本均值的定义，n 为样本数。

$$\bar{x}=\frac{1}{n}\sum_{i=1}^{n}x_i$$

其中 x_i 是第 i 个样本值。

| 符号 | 含义 |
| --- | --- |
| $n$ | 样本数 |
```

预期：公式来源为原始文本，表格内也能排版。把末尾 `$$` 或 `}` 删除后另存一份测试资料，应出现结构失败提示，不能将残缺式发布为完整证据。核验后可按界面正常删除自己的测试资料。
