# K02 图文增量实施计划

日期：2026-10-28。用户要求“把这些也补上”，承接公式增量：补插图裁剪保存、图文及题号关联、检索引用展示、回答读取相关图片。保留现有脏改动；按 Scrum + XP 先写失败测试，小步实现，最后回归及人工验收。

| 故事 | 验收条件 |
| --- | --- |
| V01 布局与裁图 | 从真实 OCR grounding 标签提取区域；安全校验坐标并裁出私有PNG；无可靠图框明确整页兜底，不伪造位置 |
| V02 保存与版本 | 资产随原件版本、解析修订、页号保存；重试/替换不串版；删除资料清理；取消或旧租约不得覆盖新结果 |
| V03 图文关联 | 保存相邻原文、标题及可靠题号；片段按范围关联图像，题号关联为启发式需核验；无描述的图片使用原页兜底，不编造图意 |
| V04 展示与访问 | 教师核验、检索引用支持鉴权图片，切换和撤权清理旧图；不使用公开图片目录、不把令牌放入URL |
| V05 回答读取 | 默认复用已配置DeepSeek-OCR读取命中插图，再把观察交给文字回答模型；显式配置可用视觉回答模型时支持直接图片输入。限定图数/容量，失败和能力降级明确提示 |
| V06 验证与证据 | 模拟布局/协议/授权测试、真实课件OCR与看图调用、真实MySQL、前端交互与视觉检查；记录失败和限制，不把识别成功算作理解正确 |

新增截图PNG及元数据使用私有数据库资产表保存，删除随资料级联，避免产生无主公开文件。单图、每页及单修订总容量有限；超限明确留核验问题。公式继续保存LaTeX；局部图、原页与图文说明共同保留。旧资料需重新解析。

范围不包含自动解答全部试卷、数学正确率保证、手写批改、语义精准分题或教师审批工作流。先完成资料图文链；K03的通用检索融合质量仍单独验收。

实施结果：V01–V06的代码与验证流程已完成。后端360项中346通过、14跳过；前端21项页面和8项渲染通过；真实MySQL、真实课件3页图像保存及读取复验通过。数值表拦截和保守文字回退有真实失败/修复证据；直接视觉回答模型尚未配置实测，不能把代码支持写成已完成语义质量验收。详见 [测试报告](K02-visual-test-report.md) 与 [人工验证](K02-visual-manual-verification.md)。
