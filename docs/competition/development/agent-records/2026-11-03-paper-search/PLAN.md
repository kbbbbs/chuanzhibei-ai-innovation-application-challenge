# 论文检索诊断与修复

用户要求：先尝试修复论文检索功能。暂停此前push准备，未提交、未推送。

范围：从既有arXiv超时记录出发，先实际HTTP复现并核实返回论文结构；对可复现故障先记录RED，再修复，再验证。根代理负责产品改动，Terra负责测试代码、运行与证据。

初步反馈：两次arXiv请求业务200，尚需核对论文数据与原查询词。暂不能认定此前一次超时是固定代码缺陷或已经修复。

可证伪假设：
1. 短暂网络/上游故障：相同关键词重复请求可以恢复。
2. 上游错误Atom被当正常论文解析：受控api/errors feed会被错误标成功。
3. 失败与空结果混淆：受控业务超时/网络错误后页面出现未找到结果，而不是持久错误及重试入口。

验收：正常非空和空结果保留；超时、不可达、429/5xx、错误feed明确失败；页面区分失败和无结果，并能重试恢复。真实API复验需看到有效论文，不以HTTP200或模型名称代替成功。外部服务瞬时可达性不能由本地修复保证。
