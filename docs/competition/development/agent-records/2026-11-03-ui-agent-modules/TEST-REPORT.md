## 新发现：P1分类写权限缺失

有效学生账号可通过 `POST /categories` 新增分类，并通过 `PUT /categories/{id}` 修改，已两次真实复现并确认持久化；匿名请求被拒绝。前端分类管理仅管理员可见，但 `CategoryController` 的add/update没有对应角色检查，登录拦截器只负责身份认证。

只操作本轮合成分类，已由管理员清理。删除入口也缺少显式角色校验属于静态风险，本轮没有执行学生删除或级联删除课程。此缺陷未在本轮界面修复中擅自修改后端，仍待优先修复。可复现脚本：`node docs/competition/development/agent-records/2026-11-03-ui-agent-modules/modules/smoke.mjs --permissions-only`。

早期将学生 `GET /users` 返回200判为越权是测试预期错误，后续核对仅返回当前学生自己，密码字段不存在，跨用户读取被拒绝；已明确纠正，不列为产品缺陷。
