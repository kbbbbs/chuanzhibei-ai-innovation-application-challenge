# 结果与人工验证

## 实际发现

原逐页核验抽屉只有预览、文本展示、重试和强制识别。原前端漏掉 OCR_READY 状态映射。OCR 与公式解析会保守标记 needsReview，因此有大量需要人工检查的页。

用户随后提供 http://192.0.2.11/app/teacher-knowledge-base，并说明是右侧抽屉。服务器 HTML 可读取，入口引用 NativeKnowledgeWorkspace-CLkvtT4R.js。只读检查该已部署资源，包含“逐页核验”，缺少“修改文本”“保存并确认本页”“确认本页无误”。浏览器已登录标签页绑定两次超时，未完成实际抽屉交互验证。没有修改服务器。

## 本地实现

资料所有者可确认原文本或修改后确认。保留原文、OCR 原结果与历史页面，存储确认人、时间及来源解析修订。确认创建新解析修订，通过既有后台处理重建检索索引。旧索引在新索引激活前继续可用。拒绝越权、处理中写入、旧版本写入、无效位置、非空白页的空文本及结构不完整公式。保留其他页的成功、失败、空白状态。页面记录不完整时要求重新解析全部。

前端保存冲突显示错误并保留编辑内容。增加已人工确认状态，补齐 OCR_READY 的已识别显示。一次确认后等待索引任务完成再操作下一页。这是本轮选择的交互，未增加批量确认。

## 更新后的人工验证方法

以资料所有者登录教师知识库，进入“逐页核验”。对照原页检查文字、表格、公式和配图。正确时点“确认本页无误”，有误时点“修改文本”并“保存并确认本页”。等待后台索引完成后刷新，应出现“已人工确认”，核验列表减少该页。用修改后的特征词检索，确认来源页码及修订内容。失败页可手工补正文或强制识别。
