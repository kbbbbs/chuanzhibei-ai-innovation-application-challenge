一、已经转为本项目主体的能力（代码归属）

1. 资料管理、解析与索引
实现文件：ai-learning-backend/src/main/java/com/cupk/aiacademy/rag/NativeRagService.java、RagDocumentParser.java、RagBm25.java、RagEmbeddingClient.java。
自有数据模型：native_rag_base（owner、名称、描述、显式shared）、native_rag_document（原始文件、散列、类型、体积、页数、片段数、embedding状态）、native_rag_chunk（document/kb ID、页码、序号、文本、可选向量及模型指纹）。
关键字段与接口归属：base.owner_id/shared控制读写；document.id/kb_id/file_name/file_key/sha256/mime_type/file_size/page_count/chunk_count/embedding_status表示真实原件及索引；chunk.id/document_id/kb_id/page_number/ordinal_number/content/vector_json/vector_model定位片段及向量。对外经NativeRagController的/api/rag接口访问，RagSearchHit把数据库page_number/ordinal_number映射为page/ordinal。上传同步解析成功后才事务写入文档/chunks；列表parseStatus/parse_status=success、parse_progress=100由有效文档派生，数据库没有独立持久化parse_status列或异步解析任务表；上传失败返回明确错误，备课SourceFile另存失败状态。这些字段以database/native_rag.sql及NativeRagService为准。
数据库和文件保存、解析、分块、关键词排序、向量调用适配、访问控制均为本项目代码，不再依赖 WeKnora 的知识库接口。
基础依赖 PDFBox / POI / Spring / 数据库和基础模型 API 仍应在提交材料中声明；使用基础库并不表示核心工作由外部知识平台代做。
解析格式：PDF、DOC、DOCX、PPT、PPTX、MD、UTF-8 TXT。
明确边界：最大 20 MB、PDF/幻灯片最多 500 页、文本最多 100 万字；同一库按原文件散列去重；普通文档没有可靠页码时page为空。
扫描 PDF 自动 OCR 尚未接入原生解析器；完全没有可抽取文字的文件明确拒绝，不显示虚假的“已成功解析”。混合扫描/文字PDF的图片内容也不能宣称已解析。

2. 检索方式与自研范围
默认实际运行方式是 BM25 关键词检索，是本项目自有的片段检索与增强生成基线。
RagEmbeddingClient 是可选基础模型向量接口，配置 RAG_EMBEDDING_* 后可给文档建立真实向量；向量模型指纹随文档片段保存。
检索响应 mode/warning 说明本次实际是 bm25 或 hybrid，以及配置缺失、服务不可用、文档缺向量等明确降级情况。
本轮真实服务摘要的retrieval.mode和Agent.mode均为bm25；原生资料检索命中1片段，Agent返回1个实际匹配的citation。
实现了可选向量调用不等于已经实际测过远程向量服务，不得把当前默认 BM25 演示称为语义向量检索。
向量检索和事实准确率的效果仍应在真实教学材料上做对照验证；引用编号合法不等于答案每句话都已经被事实核验。

3. 原生知识库问答
实现文件：rag/chat/NativeRagChatService.java、NativeRagChatController.java、GroundedAnswer.java。
数据模型：t_native_rag_session、t_native_rag_message；历史消息保留本轮生成时的结构化来源快照。
问答先按当前用户获取授权片段，再生成，最后按给定编号检查引用；无法检索证据时明确返回 NO_EVIDENCE；引用检查失败时回到本次检索的真实摘录。
普通JSON接口 /api/rag/chat 与POST流式接口 /api/rag/chat/stream 均已实现；流式阶段有 progress/delta/complete/error 事件。
前端以 complete 的已核验正文替换流式临时正文；流式delta在最终编号校验前只是临时输出，不可宣称每个已流出的token均已经通过引用检查。

4. 本项目 Agent
实现文件：agent/knowledge/NativeKnowledgeContextProvider.java、KnowledgeContextProvider.java、AgentPromptAssembler.java、AgentChatService.java、AgentDefinitionService.java；AgentChatResponse/AgentMessageResponse。
本轮让 Agent 的实际资料检索和上传绑定转为原生知识库；返回/历史保留citations、retrievalMode、knowledgeStatus、knowledgeWarning。
已有教学业务规划、读工具、写操作确认仍复用本项目 Agent 系统。
Agent会话聊天仍是普通JSON响应，不是原生知识库SSE问答的同一接口；前端loading/streaming状态字段不能证明Agent实际逐token流式生成。
兼容单轮chatOnce/旧chat入口已加入返回前来源权限和编号校验，但返回类型仍是String，没有结构化citations；不得因会话聊天新增citations就宣称所有旧入口均可点击溯源。
选中课时原文仍由前端拼入自由文本参考上下文；目前不能宣称已实现服务器验证的lessonId/documentId上下文绑定。

5. 备课与题库
PreparationService 已完全去掉 WeKnora 依赖：原生创建/上传、按document ID核验状态、原生检索、原文概览和大纲/课时/题目生成。
创建/更新配置、开工及后台工作线程检查知识库可读性；后台使用持久化project.teacherId，不依赖请求线程的UserContext。模型完成后的统一completeGeneration再次核验绑定库，共享在调用期间撤销时不写入完成草稿。
资料检索或读取失败中断生成并保存可重试失败状态，不再静默退成普通模型补写。
关键词无命中时可按授权文档顺序选择前部片段，明确标注这是一种整体备课资料选择策略，不称为问题相关性命中。
课时contentMd及题目analysis确定性附加“生成参考资料（供教师核验）”，含本次实际doc/chunk/page和摘录；这种记录不是逐句或逐题事实核验。
原生重复文件不重复SourceFile；已删除的上传资料明确提示重新上传，不能一直假称等待解析。
QuestionService 的PDF提题不再创建外部会话：直接解析本次上传文档chunks并用本项目模型网关提取已有题目。
单次PDF提题上下文上限为12000字（含出处说明），超限明确要求拆分文档后重试；不能宣称可单次完整提取任意长PDF。
KB出题转为原生检索/授权资料概览；操作用户控制资料权限，teacherId用于题目作者，管理员代教师操作时两者不混淆。PDF提题、默认模型网关与选定model/temperature三种返回路径都在完成后复查本次资料授权。
备课/出题模型调用边界及题库JSON解析对外返回明确重试提示，不把原始provider响应或模型原始输出拼进错误消息；选定model/temperature的原有路由保留。
