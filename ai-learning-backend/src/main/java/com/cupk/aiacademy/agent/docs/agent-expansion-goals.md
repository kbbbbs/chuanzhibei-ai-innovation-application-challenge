# Agent 功能拓宽目标文档

## 目标

把当前 Agent 从“课程模块自然语言 CRUD 验证可用”拓宽为覆盖教学平台核心业务的系统 Agent。

最终目标不是让模型直接写库，而是让模型负责理解用户意图和抽取参数，所有写操作仍然通过本地 schema、确认动作、权限校验、业务执行器和审计日志完成。

## 设计原则

1. Schema 优先：每个可执行动作必须声明 `AgentActionSpec`，包括动作编码、风险等级、参数类型、别名、枚举、示例、影响说明和 TTL。
2. 写操作必须确认：所有创建、修改、删除、状态变更、批量处理都必须生成 `pendingAction`，用户确认后才执行。
3. 执行器兜底：模型抽取结果只作为候选参数，最终由执行器校验权限、数据归属、状态范围、唯一定位和业务约束。
4. 前端只信结构化数据：前端确认按钮以 `pendingAction.actionId/actionCode` 为可信来源，不依赖大段文本解析。
5. 审计可追踪：所有确认执行成功的写操作必须记录操作者、动作、参数、结果和影响数据。
6. 先单动作，后流程编排：先把各模块 CRUD 做稳，再做“创建课程并添加章节”“发布考试并通知学生”等跨模块流程。

## 能力分层

### L1：单模块 CRUD

目标是让用户用自然语言完成单个模块的创建、修改、删除、状态变更和查询。

优先模块：

1. 课程
2. 通知
3. 章节、课时、课程资源
4. 教学班和班级学生
5. 作业和作业提交
6. 考试、试卷、题库
7. 成绩

### L2：批量操作

在单条动作稳定后，增加批量动作。

典型能力：

- 批量加入学生
- 批量移除学生
- 批量调整章节或课时顺序
- 批量组卷
- 批量批改
- 批量导入成绩

批量动作必须额外提供影响预览和强确认。

### L3：跨模块流程

把多个 pending action 编排成一个流程，用户可以逐项确认或整体确认。

典型流程：

- 创建课程，同时创建第一章和第一个课时
- 创建教学班，同时加入学生名单
- 发布考试，同时给教学班发送通知
- 布置作业，同时生成课程通知
- 创建试卷，同时添加指定题目

### L4：智能查询与分析

查询类不需要确认，但必须做权限过滤。

典型能力：

- 查询课程、章节、课时、作业、考试、成绩
- 查找未交作业学生
- 分析考试平均分和低分学生
- 生成班级学习进度概览
- 给教师提供教学风险提醒

## 模块落地标准

一个模块算完成，至少满足以下条件：

1. 有清晰的动作清单和动作编码。
2. 写动作都有 `AgentActionSpec`。
3. 参数抽取支持模型抽取和本地 fallback。
4. 缺失参数能生成待确认动作或明确提示用户补充。
5. 确认执行接口能用 `actionId` 执行。
6. 执行器有权限校验、参数校验、数据归属校验和业务状态校验。
7. 成功执行后写审计日志。
8. 前端确认弹窗能自动回填 actionId、actionCode 和参数。
9. 成功或失败后给出明确结果和对应管理页入口。
10. 至少覆盖参数抽取、意图路由、执行器三个层面的测试。

## 推荐里程碑

### M1：课程样板稳定

目标：课程创建、修改、上下架、按标题定位、按 ID 定位、错误提示、前端确认全部稳定。

完成后课程模块作为其他模块迁移模板。

### M2：低风险模块拓宽

目标：通知、章节、课时、课程资源完成单动作闭环。

这些模块和课程强相关，适合验证 schema-first 路线的可复用性。

### M3：教学组织模块

目标：教学班、班级学生完成创建、修改、状态变更、添加/移除学生。

重点是权限和学生身份校验。

### M4：作业与考试模块

目标：作业、作业提交、考试安排、试卷、题库完成核心写操作。

重点是高风险确认、影响预览和状态约束。

### M5：成绩和批量能力

目标：成绩录入、修改、删除、批量导入、批量处理能力落地。

成绩模块风险最高，必须在前面模块稳定后再扩展。

### M6：流程编排

目标：把多个单动作组合成可确认的流程计划。

流程编排不绕过单动作执行器，每一步仍然是独立可审计动作。

## 暂不做的事

1. 不让模型直接执行数据库写操作。
2. 不优先做完整 ReAct 或自动 plan-replan。
3. 不先拆成独立 MCP Server。
4. 不把整个数据库 schema 暴露给模型。
5. 不在缺少唯一定位条件时自动猜测目标数据。
