# Agent 功能拓宽进度文档

更新日期：2026-07-10

## 当前结论

当前路线已经从“关键词规则路由 + 模型自由回复”收敛为“轻量统一意图选择 + 单 Schema Planner + 校验修复循环 + pending action 确认 + 本地执行器校验 + 审计日志”的系统 Agent 路线。

这条路线更适合本项目：模型负责理解自然语言，本地代码负责安全执行。

## 已稳定的基础能力

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 轻量统一意图选择 | 已完成第一版 | `LlmIntentSelector` 只读取工具代码和摘要，一次选择 `CHAT/READ/WRITE`，不再让读写 Planner 分别遍历完整工具 Schema。 |
| 单 Schema Planner | 已完成第一版 | 意图选择完成后，只把选中的一个 action 或读工具完整 Schema 发送给参数规划模型。 |
| 校验修复循环 | 已完成第一版 | 非法 JSON、动作码、字段、类型、必填和二选一约束会结构化反馈给模型，默认最多修复 1 轮。 |
| 模型读工具选择 | 已完成第一版 | 统一选择器确定读工具后，读 Planner 只提取该工具参数；后端校验、修复后执行，观察结果再进入最终回答，不再对 `CHAT` 额外调用模型复核。 |
| 模型调用时间预算 | 已完成第一版 | 摘要意图选择默认 5 秒，单 Schema 参数规划默认 10 秒，最终模型单次默认 15 秒，完整会话请求默认 25 秒；超时会取消调用并记录失败轨迹。 |
| `AgentActionSpec` | 已完成第一版 | 用统一 schema 描述动作、参数、风险、确认文本和影响说明。 |
| 写参数生成 | 已完成第一版 | 生产聊天链由 LLM Planner 直接按 action schema 生成参数；旧 `AgentParameterExtractor` 只随遗留 PlanTool 保留，不参与当前聊天路由。 |
| pending action | 已完成 | 仅校验通过的写操作生成待确认动作，统一持久化到 `t_agent_pending_action`。 |
| 高风险确认 | 已完成 | 高风险动作需要确认文本。 |
| 执行器权限校验 | 已完成基础闭环 | 执行前重新校验角色、归属、参数和业务状态。 |
| 审计日志 | 已完成基础闭环 | 确认执行成功后写操作日志。 |
| 前端确认入口 | 已完成第一版 | 聊天页和首页浮窗使用结构化 pending action，执行前重新从数据库校验 actionId。 |
| 模型健康检查 | 已完成 | 可以定位模型认证、超时、限流等问题。 |

## 当前优先级

### P0：课程样板收尾（已完成）

- 课程分类名称到 ID 解析：`CourseCreateActionExecutor`/`CourseUpdateActionExecutor` 支持 `categoryName`，名称不唯一时要求补充 `categoryId`；`CourseCreatePlanTool`/`CourseUpdatePlanTool` 的 `categoryId` 改为可选并新增 `categoryName` 参数。
- 课程详情/课程管理跳转参数：前端 `actionLinkFor` 在确认结果含 `courseId` 时深链到 `/courses/:id`（课程详情），否则回退课程管理列表。
- 课程下架前影响预览：`CourseStatusActionExecutor` 返回 `impactPreview`，包含受影响章节数、课时数、教学班数和学生数，并在下架时标记 `offline`。
- 中文表达测试：补「停用课名叫 Java 入门的课程」「恢复 Java 入门 课程」意图路由测试，以及分类名称解析、影响预览执行器测试。

### P1：通知模块完整 CRUD

- `notice.create`（已完成）
- `notice.update`（已完成）：支持按 noticeId 或原通知标题唯一定位，修改标题、正文、通知类型和目标教学班；教师只能修改自己发布的通知。
- `notice.status`（已完成）：高风险动作，支持撤回（0）/发布（1），删除类表达映射为撤回，不物理删除通知记录。
- 通知列表和详情跳转（已完成）：新增前端 `notice.js` API、`NoticeList` 视图（列表/详情抽屉/发布/编辑/删除）、`/notices` 路由、导航菜单，以及 agent 确认后 `notice.*` 动作深链到通知管理。

通知模块已作为第二个完整样板迁移完成，验证了课程样板的可复用性。

### P1：章节、课时、资源模块

- `chapter.create/update/delete/sort`
- `lesson.create/update/status/sort`
- `course.resource.attach/remove`

重点是自然语言定位，例如课程名、章节名、第几章、第几个课时。

### P2：教学班和作业模块

- 教学班创建、修改、结束、恢复。
- 学生加入、移除、休学/恢复。
- 作业发布、修改、删除、批改。

重点是权限、学生定位和时间解析。

### P3：考试、试卷、题库、成绩

这些模块风险高，必须在前面模块稳定后推进。

重点是强确认、影响预览、批量操作和状态约束。
